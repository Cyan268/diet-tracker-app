# 饮品目录的数据边界与维护方式

## 当前实现

饮品目录分成两层：

- `assets/seed/seed-drinks.json` 保存通用杯型、糖度、奶基和小料。
- `src/data/drinkCatalog.ts` 保存主流品牌的代表单品、标准杯估算值和奶基规则，并在初始化时转换成 SQLite 种子数据。

页面通过 Repository 查询品牌、单品和选项。单品级糖度/奶基规则优先于通用规则：例如“瑞幸咖啡 / 标准美式”只返回“无”奶基，不会再混入全脂牛奶、燕麦奶；没有单品规则时才回退到通用选项。

## 为什么不是“完整且永久正确的品牌菜单”

现制饮品菜单会随地区、季节、杯型、冷热、门店和配方持续变化。很多品牌也没有提供稳定、可机器读取、覆盖全部 SKU 的公开营养 API。因此当前目录定位是“方便日常记录的代表产品基线”，不是品牌官方营养数据库。

UI 对所有品牌数值标注“估算”，同时显示目录版本。该目录不能被描述为“精确覆盖全国所有门店菜单”。生产版本需要进一步增加：

1. 服务端版本化目录和增量更新，不再依赖 App 发版。
2. 每个 SKU 的来源 URL、采集时间、地区、杯型、冷热和可信度。
3. 官方营养数据优先；缺失时使用配方估算并允许用户修正。
4. 过期检测、审核后台和历史版本，避免菜单更新后影响旧记录。

## 本轮参考的公开来源

- [蜜雪冰城产品实力](https://www.mxbc.com/product_strength.html)：冰鲜柠檬水、草莓摇摇奶昔、茉莉奶绿、雪王雪顶咖啡等代表产品。
- [1点点饮品介绍](https://www.alittle-tea.com/ourdrinks/chewyseries/?page=1)：品牌饮品系列和代表产品。
- [霸王茶姬产品页](https://chagee.com.hk/product/fresh-milk-tea-series)：伯牙绝弦、桂馥兰香等原叶鲜奶茶。
- [茉莉奶白产品分类](https://cn.mollytea.com/product-categories-cn/)：一朵茉莉花、茉莉奶白冰茶等产品。
- [瑞幸咖啡产品信息](https://www.lkcoffee.com/products)：部分单品直接公开热量、咖啡因和默认规格，本目录优先采用其公开值。
- [奈雪的茶品牌页面](https://www.naixue.com/about)：品牌公开的代表产品。
- [CoCo都可品牌介绍](https://www.coco-tea.com.cn/detail/136.html)：鲜百香双响炮、奶茶和果茶产品线。

除品牌明确公开的数值外，目录中的 kcal、糖和咖啡因都是标准杯工程估算，应由真实营养数据库或品牌数据替换。

## 设计取舍

“菜单名称”和“营养事实”是两类数据。产品名可以来自品牌公开菜单，但没有官方规格和营养表时，不能把估算包装成事实。因此目录包含版本、估算标签和单品覆盖规则，历史记录仍保存营养快照。后续服务端目录应补充来源、地区、规格、可信度和审核流程。
