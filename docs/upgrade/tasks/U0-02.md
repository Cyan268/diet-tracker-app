## 面试追问

1. **数据库自增 ID 为什么不能直接保证增量同步不漏数据？**
   自增表示取号顺序，不是提交顺序。A 取 11 暂停，B 取 12 提交，客户端推进到 12 后会错过迟交的 11。方案让同用户写入先锁同步状态行，再在同事务里改日志、递增行内序号、写事件；B 必须等 A 结束才写。代价是单用户写入串行，需要覆盖所有入口并在真实 PG 验证。当前是设计，不能说已修复上线。
2. **AI 确认成功但响应丢失，怎么避免重复记录？**
   客户端发送前持久保存确认键和请求；服务端唯一约束加请求 hash，并把整批日志、事件、确认映射和纠错一次提交。重试同键同内容找回原结果，不再创建。客户端走远端应用而不是 addLogs，不生成第二份 create Outbox；结果未知时不能另存手工记录。成本是在线依赖和恢复状态机。
3. **为什么用了租约和幂等，还不能保证模型只扣一次钱？**
   租约 token 只能阻止过期 Worker 覆盖本项目数据库。模型执行和数据库提交不是一个事务，超时可能已经计费。每次 Attempt 单独记录；供应商支持且验证过幂等/查询时恢复，否则 unknown 默认不自动重发付费请求，提示用户风险后决定。保证范围是本项目只接受一个有效草稿，而非外部计费 exactly-once。
