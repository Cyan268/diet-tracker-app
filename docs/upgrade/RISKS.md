## R03 的推理依据与实验边界

PostgreSQL 的 sequence 分配不等于业务事务提交；Read Committed 查询只看到语句开始前已提交的行。因此从代码可构造如下风险时序，但本轮 Docker 未运行，尚未对项目执行这个故障实验。[PostgreSQL 17 事务隔离官方文档](https://www.postgresql.org/docs/17/transaction-iso.html)

```text
同一用户，不同日志：
A: 分配事件 101 ── 暂停 ─────────── 提交 101
B:                  分配/提交 102
客户端:                         拉到 102，after=102
下轮: id > 102 不包含迟到的 101
```

单调、自增、唯一约束、同事务写事件分别解决不同问题；三项既有 PG 竞争测试只验证 create 去重、版本更新、令牌轮换，不覆盖该时序。

## 边界

- 不因为风险列表存在就判定现有所有离线功能失效；正常链路与故障保证分开描述。
- 不为修复风险清除用户本地库、删除生产卷、重写已发布迁移或放宽 owner 校验。
- 不重复实现已有认证、助手、周报、Provider、营养算法和限流模块。
- Worker 幂等、租约与外部费用未知策略尚属规划；不能把未实现的能力写进简历。
