# NutriPilot 开发与学习路线

## 总体原则

项目的最终目标不仅是“功能可运行”，还包括：

- 代码可以被测试、部署和维护。
- AI 输出可以被验证、评测和降级。
- 每个关键设计都能说明取舍，而不是只会复述代码。
- 简历中的每个技术点都有真实代码、数据或演示支撑。

每项任务完成时必须同时交付四类内容：代码、测试、学习记录、面试问答。

## Phase 0：工程化基线

目标：把当前单机应用整理成适合持续开发和公开展示的代码仓库。

任务：

- [x] 建立正式 README 和文档目录
- [x] 建立学习日志、面试题库、指标记录和 ADR
- [x] 添加 ESLint、Prettier 和统一脚本
- [x] 添加单元测试框架
- [x] 为营养计算、目标计算和提醒规则补充测试
- [x] 配置 GitHub Actions：类型检查、Lint、测试
- [x] 清理未使用依赖和主要 `any` 类型
- [x] 设计 SQLite 版本迁移机制

验收标准：

- 一个命令可以完成类型检查、Lint 和测试。
- CI 能阻止不通过检查的代码进入主分支。
- 核心确定性业务逻辑具备测试。
- 新开发者仅阅读 README 即可运行项目。

重点学习：TypeScript 类型系统、静态检查与测试的区别、单元测试边界、CI/CD 基础、数据库迁移。

## Phase 1：全栈后端与离线同步

目标：从本地单机应用升级为具备用户系统和云端数据的全栈应用。

建议技术：FastAPI、PostgreSQL、SQLAlchemy、Alembic、Redis、Docker Compose。

任务：

- [x] 创建后端服务和分层目录
- [x] 分环境配置、异步数据库连接和健康探针
- [x] 后端 Ruff、Pytest、覆盖率和 CI
- [x] 精确依赖锁与 Alembic 离线 SQL 验证
- [x] PostgreSQL 核心数据模型与 Alembic 迁移（用户 v1、刷新令牌 v2、饮食领域 v3）
- [x] 注册、登录、Access Token、Refresh Token 轮换与重放检测
- [x] 用户资料、私有食品、饮食记录和每日统计 REST API
- [x] OpenAPI 文档导出、客户端类型生成与 CI 漂移检查
- [x] Expo 登录注册、SecureStore 会话、自动刷新和离线启动
- [x] SQLite 本地账号隔离和 Outbox 推送队列
- [x] 云端游标增量拉取和删除墓碑
- [x] 幂等写入、失败重试和冲突解决 UI
- [x] Docker Compose 一键启动并验证 PostgreSQL、Redis、API 健康检查与真实迁移
- [x] 真实 PostgreSQL 幂等新增、乐观锁更新和令牌轮换并发测试
- [x] 使用 k6 建立真实 PostgreSQL API 混合读写性能回归基线
- [x] Expo Web 静态预览、SQLite WASM、浏览器会话与本地 CORS 联调

验收标准：

- 用户可在不同设备登录并读取同一份记录。
- 断网时可以新增记录，恢复网络后自动同步。
- 重复重试不会生成重复记录。
- API 有鉴权、参数校验和统一错误响应。
- 固定环境、负载模型、阈值和原始压测结果可复现，且不把基线吞吐误写成生产容量。

重点学习：HTTP、REST、鉴权、关系型数据库、事务、索引、ORM、容器、离线优先同步。

## Phase 2：AI 结构化饮食记录

目标：通过自然语言和图片降低饮食记录成本。

任务：

- [x] 自然语言记录输入（首版文本闭环）
- [ ] 图片上传、私有存储与临时访问地址
- [x] 模型 Provider 抽象（规则型 Provider + OpenAI Responses Provider）
- [x] JSON Schema/Pydantic 结构化输出
- [x] 食品实体匹配和营养数据检索（本地目录首版）
- [x] 置信度展示和用户确认页面
- [ ] 超时、重试、熔断和规则降级（已完成超时、有限重试和规则降级；熔断待实现）
- [x] AI 调用日志与成本统计（Token 已记录；价格需按部署环境显式配置）
- [x] 用户级 OpenAI API Key 配置（服务端 AES-GCM 加密、按用户隔离、仅回传末四位）

验收标准：

- 模型 API Key 不出现在客户端。
- AI 结果不能未经确认直接写入正式饮食记录。
- 所有模型输出必须通过 Schema 校验。
- 营养数值由数据库和确定性算法计算，不由模型直接生成最终值。

重点学习：多模态模型、Prompt 设计、结构化输出、模型幻觉、实体消歧、人机协同、异步任务。

## Phase 3：Tool Calling 助手、周报与 AI 评测

目标：让 AI 基于真实用户数据提供可解释建议，并证明系统效果。

任务：

- [x] 实现 `get_today_summary`、`get_weekly_trend`、`search_food` 三个用户隔离只读工具
- [x] 对话状态和消息持久化（用户隔离、最近四轮裁剪、刷新恢复、删除与幂等消息 ID）
- [x] AI 饮食助手（多轮 Tool Calling、证据展示、规则降级）
- [x] 个性化周报（双周确定性事实、记录完整度、严格结构化叙事、规则降级与事实指纹）
- [x] 建立脱敏评测集（首版 26 条中文输入、32 个期望实体）
- [ ] 评测 Schema 合法率、识别准确率和用户修改率（前两项已完成，用户修改率待埋点）
- [x] 评测 P50/P95 延迟、Token 和可选单次调用成本（真实公网模型基线待用户显式运行）
- [x] Prompt/模型版本化和回归测试

验收标准：

- AI 的数据结论能追溯到工具返回值。
- 模型不可用时核心记录功能仍可使用。
- 每次 Prompt 或模型变更都有自动评测结果。
- README 展示真实而非编造的项目指标。

重点学习：Tool Calling、Agent 边界、上下文管理、AI Evals、可观测性和成本优化。
